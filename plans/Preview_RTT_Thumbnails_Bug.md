# 🐞 Баг: миниатюры типов тайлов в редакторе пропадают (Bevy 0.19)

> **Статус:** 🔴 ОТКРЫТ
> **Ветка:** `feat/bevy-0.19`
> **Компонент:** `crates/editor_client` (верхняя панель редактора карт)
> **Дата:** 2026-09-26

---

## 1. Симптом

В верхней панели `editor_client` — 5 миниатюр типов тайлов (Cube, Wedge S/W/N/E),
отрендеренных offscreen-камерами в текстуры (`RenderTarget::Image`) и показанных
через `ImageNode`. Часть миниатюр **не отображается**: на их месте виден только фон
кнопки (серый). Набор пропавших меняется от запуска к запуску.

### Точное поведение (со слов пользователя + подтверждено замерами)

1. Наведение мыши на кнопку подсвечивает её серой рамкой.
2. **Если провести мышью медленно** — миниатюра пропадает и **остаётся серой навсегда**
   (для этой кнопки).
3. **Если провести быстро** так, что серая подсветка лишь мигнёт — миниатюра
   переживает наведение, и **после этого на этой кнопке она больше не пропадает**
   при любом движении мыши.
4. Итог: «судьба» миниатюры решается при **первой** привязке UI к текстуре.

## 2. Как воспроизвести (инструменты уже есть в репозитории)

В debug-сборке оба бинарника поднимают локальный control-API на `127.0.0.1:15703`
(см. [Control_Server_Plan.md](Control_Server_Plan.md) и
`.agents/skills/klep2tron-control/SKILL.md` — там полная документация).

```bash
cargo run -p editor_client                       # сервер включён автоматически (debug)
S=http://127.0.0.1:15703
curl -s $S/state | python3 -m json.tool | head   # состояние
# войти в редактор: Down (до LEVEL EDITOR) + Enter
curl -s -X POST $S/key -d '{"key":"ArrowDown"}'; curl -s -X POST $S/key -d '{"key":"Enter"}'

# медленное наведение (воспроизводит баг): «держать» наведение на кнопке
curl -s -X POST $S/ui_hover -d '{"label":"Wedge S"}'
sleep 1
curl -s -o /tmp/shot.png $S/screenshot
```

Детектор миниатюр (по каждому элементу):

```bash
python3 -m venv /tmp/imgvenv && /tmp/imgvenv/bin/pip install pillow
/tmp/imgvenv/bin/python \
  .agents/skills/klep2tron-control/scripts/preview_check.py /tmp/shot.png
# вывод: [5-555] -> позиции 1..5 = Cube, WedgeS, WedgeW, WedgeN, WedgeE
#        '5' = миниатюра есть, '-' = пусто
```

Замеренные примеры (до/после наведения):

```
p_base1.png      [5-555]   # WedgeS пустой с самого начала
p_hover_wn.png   [--555]   # после наведения на Wedge N пропал ещё и Cube
```

## 3. Что уже пробовали (НЕ помогло)

| Попытка | Результат |
|---|---|
| Разные `Camera.order` у 5 превью-камер (были одинаковые `0`) | частично: перестало «залипать» навсегда у одного типа, но пропажи остались |
| `unlit: true` у материала превью (проверка гипотезы «свет не применяется») | не помогло |
| `asset_usage: RenderAssetUsages::RENDER_WORLD` у текстуры превью (убрать main-world копию) | не помогло |
| **Одна** камера вместо пяти (ортографическая, ряд из 5 тайлов в одну текстуру, UI режет через `ImageNode { rect }`) | симптом **тот же** (5→4→3) — значит, дело **не в количестве камер** |
| Событийный показ: `Screenshot::image(handle)` + `ScreenshotCaptured` как сигнал готовности | **стало хуже**: readback ломает таргеты, все миниатюры пустые |
| Скрыть `ImageNode` и показать через N кадров | **сейчас в коде** (N=30). 24/24 кадров `[55555]` при обычном тесте, **но медленное наведение всё равно роняет** |

## 4. Что установлено точно

- Все 15 сущностей превью (5 мешей + 5 камер + 5 источников света) **живы**, когда
  миниатюры пустые: `curl -s $S/state` показывает их (y≈1000 меши/камеры, y≈1002 свет).
  **Никто их не деспавнит.**
- Пропадает именно **рендер/привязка текстуры**, а не сущность.
- В логе **нет** ошибок рендера (`Validation Error` и т.п.).
- Набор пропадающих элементов не постоянный (то `-` на WedgeS, то на Cube, то 2 сразу).

## 6. Гипотезы для следующего шага

1. **Гонка при пересборке UI-узла.** Наведение меняет `BackgroundColor` кнопки →
   UI пересобирается → `ImageNode` заново байндит текстуру. Если в этот момент
   рендер-текстура «не готова», привязка становится пустой и **не восстанавливается**.
   Проверить: в `Last`/`PostUpdate` логировать, меняется ли `ImageNode` и
   пересоздаётся ли bind group; либо временно убрать смену фона на hover и
   проверить, исчезнет ли баг.
2. **`RenderLayers` + `VisibleEntities`.** Попробовать полностью убрать
   `RenderLayers` у превью (разнести сцены по расстоянию/слоям иначе), чтобы
   исключить фильтр видимости.
3. **UI-текстуры рендер-таргетов в 0.19.** Сравнить с минимальным примером
   Bevy 0.19 «камера → `RenderTarget::Image` → `ImageNode`»: воспроизводится ли
   пропажа при пересборке UI. Если да — это баг Bevy, оформить issue.
4. **Запекание.** Как обходной путь (не фикс): один раз отрендерить ряд из 5
   тайлов в текстуру и скопировать результат в **обычный** `Image` (не живой
   render target), затем использовать его в UI. Минус — превью перестанут
   крутиться вслед за камерой.
