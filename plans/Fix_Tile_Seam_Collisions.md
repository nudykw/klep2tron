## 1. Цель и Проблема

**Проблема:**
1. При движении по ровному полу персонаж (`ActorRoot`) периодически застревал на швах между тайлами (`x = 2.5`, `x = 4.5` и т.д.).
   * Причина: `Collider::cylinder` имел плоское основание и острые 90° кромки. Из-за микропроседания в пол под действием гравитации дискретный солвер Avian3D/Parry3D упирал кромку цилиндра в вертикальную грань соседнего кубика пола (internal edge / ghost collision).
   * Причина: пол состоял из 256 независимых кубических коллайдеров `1×1×1`.
2. В узких проходах шириной ровно в 1 тайл (ширина коридора 1.0, диаметр робота 0.72) касание стены вызывало торможение из-за дефолтного коэффициента трения `Friction = 0.5`.

**Цель:**
Робот непрерывно и гладко перемещается по комнатам и узким коридорам любой протяженности, не спотыкаясь о швы пола и не залипая на стенах.

---

## 2. Требования и Ограничения

* **Обязательно:** сохранить габариты персонажа (радиус и высота рассчитываются из AABB запечённой модели робота).
* **Обязательно:** сохранить единый источник истины `rendering::tile_geometry` для геометрии тайлов.
* **Обязательно:** кроссплатформенность (натив macOS/Linux + Web WASM).
* **Обязательно:** производительность: оптимизация количества коллайдеров тайлов должна снизить нагрузку на physics broadphase.
* **Зависимости:** `avian3d 0.7`.

---

## 3. Архитектура и Решение (Engineering)

### 3.1. Форма коллайдера персонажа (`actor/spawn.rs`)
Замена `Collider::cylinder(radius, height)` на **`Collider::capsule(radius, length)`**:
* Высота цилиндрической части: `length = (height - 2.0 * radius).max(0.0)`.
* Если `height <= 2.0 * radius`: используется `Collider::sphere(radius)`.
* Общая высота: `length + 2 * radius = height` (габариты идентичны цилиндру).
* Нижняя и верхняя кромки закруглены полусферами радиуса `radius`. При столкновении со швом или микроступенькой нормаль контакта имеет вертикальную составляющую, и полусфера плавно перекатывается через шов.

### 3.2. Настройка трения персонажа (`actor/spawn.rs`)
Добавление компонента трения:
```rust
Friction::ZERO.with_combine_rule(CoefficientCombine::Min)
```
* При контакте с любыми вертикальными стенами и препятствиями эффективное трение равно 0.0.
* Горизонтальная скорость робота задаётся напрямую в `player_movement_system` (`velocity.x = dir.x * SPEED`), поэтому трение о пол не требуется для разгона/торможения.

### 3.3. Жадное объединение коллайдеров пола (`physics/colliders.rs`)
Вместо создания отдельного `Collider::cuboid(1, h, 1)` на каждую клетку внедрён алгоритм **Greedy Meshing** (`greedy_cube_boxes`) для кубических тайлов (`TileType::Cube`):
1. Обход сетки 16×16.
2. Поиск максимальных прямоугольных областей `[x..=x2, z..=z2]` с одинаковой высотой `h >= 0`.
3. Создание одного объединённого коллайдера:
   * `size = Vec3::new((x2 - x + 1) as f32, height, (z2 - z + 1) as f32)`
   * `translation = Vec3::new((x + x2) * 0.5, center_y, (z + z2) * 0.5)`
4. **Результат:**
   * Внутри объединенных зон пола швы физически отсутствуют.
   * Количество `TileCollider` сущностей в комнате сократилось с ~200+ до ~15–30 (в тестовой комнате общее число сущностей в сцене упало с 1322 до 1109).
   * Снижение нагрузки на память и солвер контактов Avian.
5. Для `Wedge*` (наклонные рампы): сохраняется точная генерация колонны + `Collider::convex_hull`.
